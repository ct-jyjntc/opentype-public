# beta.15 云端历史生命周期：实现与验证

## 修复内容

旧逻辑只在保存设置时清理，并按最后更新时间计龄；更新记录可能无限延长期限。整体清空直接删除服务端行，旧设备稍后上传又会恢复。主界面也没有完整的清空入口与失败恢复提示。

本版新增固定的 `cloud_received_at`，新记录按服务端首次接收时间起算，后续更新不改年龄。老库没有原始接收时间，迁移只能采用已保存的最后服务端更新时间作为基线，不能还原此前的真实年龄。服务启动、每 60 秒及 pull/load_older/push/status 边界执行清理；不信任客户端时间。

云端到期/整体清空生成仅含 ID 与游标的云端移除标记；增量 feed 区分 `evicted` 与原有 `deleted`。客户端仅记录账户和服务器范围内的上传排除项，不调用本地历史/录音删除逻辑；迟到下载也不能覆盖这些本地副本。明确的单条跨设备删除仍优先，并可把云端移除升级为真正的全设备删除。

每次整体清空在事务内移除云端行、推进 `cloud_epoch`、保存唯一请求编号与结果。旧代际上传（包含服务器从未见过的旧 ID）返回 409；当前代际也不能上传已被移除的 ID。客户端一旦得知新代际，把当前同账户/同服务的所有已有记录排除出上传，包括离线新增记录。此选择避免根据不可信设备时钟猜测“清空前后”；明确写入界面。

本机持久化 `pending_wipe_id`，网络异常或重启后复用同一编号；已执行请求的重试返回原结果，不再清理此后新上传的内容。账户切换、取消在途上传、重复调用和存储异常有独立保护。旧服务缺少 `cloud_lifecycle_version: 1` 时，清空和保留期修改拒绝执行。

设置页提供永久/90/30/7 天、缩短保留期确认、整体清空确认、待确认请求重试、状态刷新和本机排除记录数量。整体清空可在关闭同步时显式执行，不会自动开启同步。

## 验证证据

- `npm run verify:all` 完整通过：原有客户端/原生/渲染/网关/网络等测试，服务端 215 项、联调 50 项、跨设备删除 14 组，同步从 18 组扩展至 25 组。
- 新增 `npm run test:cloud-lifecycle`：4 组旧库迁移、启动清理、失败事务回滚及账户移除测试；12 组真实 Electron SQLite + 隔离服务联调，包含文本/音频保留、离线设备、旧/新代际、持久重试、跨账户/服务隔离、原有删除传播、关闭同步、不可变年龄、边界清理、非法请求与混合分页。
- 定时测试只观察隔离 SQLite，不调用该账户 API；确认实际 60 秒定时器在没有账户访问时移除过期行。
- 同步竞态测试包含清空中止在途上传、重复清空/上传/下载互斥、账户切换后的迟到结果、重启重试、旧服务与缺失持久化拒绝、非法代际拒绝及排除项落盘失败不推进游标。
- 实际生产前端使用独立数据目录和测试代理：取消 7 天选择保留原设置；确认后 3 条云记录变为 2 条；同步后显示一条仅本地。代理在服务已提交清空后模拟丢失响应，界面显示待确认；退出重启保留待确认编号和 3 条本机记录。
- 重启后另加一条云记录，再点击“确认上次结果”：云端仍为 1 条，服务只存一次 wipe 请求，本地代际为 1 且 pending 编号清除。历史页显示原 3 条与新云记录，三份原合成音频文件逐字节相同。

证据：`tmp/cloud-lifecycle/verify-all.log`、`production-ui-verification.json`、`packaged-asr.log` 及发布目录 `evidence/`。实际 UI 使用源码生成的生产 bundle；包内相同的 17 个 JS/HTML/CSS 文件另做一致性核对，没有把源码界面验收冒充完整打包程序首次安装验收。

## 发布和边界

macOS arm64 beta.15 内置 SenseVoice Small，录音无产品时长上限。DMG 校验、严格签名、只读挂载、ASAR/原生输入库/模型一致性通过。签名为 ad-hoc，未 Apple 公证；新云协议尚未部署到生产服务。

云端移除/删除/请求编号只保留必要元数据以阻止旧设备恢复，可能随历史清理积累；账户删除会清掉这些账户元数据。清理在服务端同步事务执行，大规模账户的分批负载优化仍可继续评估。老库首次上传时间无法精确恢复。

本轮不代表真人语音质量、全部输入框、物理设备、多屏/休眠或真实生产多设备验收。旧孤立录音清理、正式签名/公证/更新、线上服务与跨平台仍在总目标中。
