# beta.13 选区提问与审阅后替换

本批继续采用 [参考材料中的选区缓存、输入环境与编辑跟踪线索](reversing-deliverables-assessment-2026-10-08.md)。不执行第三方归档脚本，也不声称恢复了其完整实现。

## 问题与实现

beta.12 的交付目标必须是可恢复的可编辑控件，因此“随便问”无法取得只读文章选区。活动 CaptureSession 又把带选区的回答当作普通结果自动插入，解释类回答可能覆盖原文。

新增 `captureCommandTarget`：只有明确的随便问模式允许在没有可编辑目标时读取选中文字；优先 AXSelectedText，兼容 AXTextMarkerRange，只读取当前元素选区，不收集整篇只读正文。普通听写保持原来的可编辑目标规则。安全/受保护字段在读取内容前被拒绝。

输入目标仍要求有效原文、UTF-16 选区与可编辑能力；读取了只读选区并不意味着它成为插入目标。网页地址沿同一元素祖先收集，包括 iframe 与父文档。任何一层命中隐私限制时，选区和上下文一起脱敏；无法确认网页来源也不提供上下文。`capturedContext` 集中实施原有敏感应用、域名与 URL 规则；DeepSeek 请求边界再次拒绝 redacted 上下文的 selected_text。

CaptureSession 的随便问结果先保存为 card，并转交给 `AnswerCardSession`。回答卡片提供复制；只有可信主进程交给它的可编辑非空选区才有替换操作。普通听写/翻译的交付方式不改变。

卡片通过新的动作 ID 接受显式替换，答案与目标在主进程固定，renderer 不提供待写文字或原生 token。IPC 只接受当前回答卡片的主 frame。点击后检查录音状态及历史仍为相同完成结果，再使用 beta.12 的目标恢复、原文检查、单次发送及内容核对。已编辑/重试/删除的历史不会被旧卡片覆盖或复活。

关闭、销毁、新卡片、锁屏、休眠、退出会撤销旧操作并释放原生句柄。发送前取消不再写入；发送后不确定状态保留并提示核对，不重复发送。重复点击被拒绝。正在录音时保留按钮，结束后可重试。历史状态写入采用事务中的现有记录条件更新，不执行 upsert；保存失败不会错误地重新开放替换。

卡片处理初始查询与更新事件的顺序，旧复制/替换 Promise 不改变新卡片。创建窗口时只发送最新 payload，避免 ready-to-show 的旧闭包恢复旧回答。上下文被保护时显示“当前输入环境的文字未用于回答”。应用帮助说明同步更新。

## 回归与实际界面

`npm run verify:all` 最终退出码 0，日志 `tmp/selection-actions/verify-all-final.log`。

- 新增 11 组 `test-answer-card`：只读无替换权限、明确点击且固定文本、重复点击、旧动作 ID、关闭/新卡片竞态、目标与历史失效、不确定结果、状态保存失败、录音中稍后重试、敏感应用/父页面/未知来源保护、真实 SQLite 条件写入及删除不复活。
- `test-capture-session` 增至 21 组，验证随便问不自动插入、转交目标后正确持有、未转交则释放、preview 使用普通听写上下文。
- `test-refinement` 增至 11 组，真实请求构造经 MockAgent 验证 redacted 的选区不会越过 DeepSeek 边界；不使用该模拟响应证明模型质量。
- 原有原生、客户端、服务端、云端删除、网络和桌面回归通过。原生冒烟不再复制任意前台选区、读取无关窗口全文或打印完整设备 ID；真实选区行为由有 PID 边界的隔离夹具验证。

通过 CUA 操作隔离 Electron 窗口与生产回答 renderer。夹具使用生产 CaptureSession、AnswerCardSession、capturedContext、InputDelivery 和真实 Swift/Koffi；提供合成 PCM 与固定回答，未调用真人麦克风或真实云模型。

1. 原生捕获只读框 `Read only selected words` 与网页正文的实际选区，提问请求收到相同选中文字，卡片无替换按钮。
2. 富文本中只选表情，生成回答时原文保持；点击替换后得到 `粗体开头【回答测试】中间` 和原第二段，前后内容保持。
3. 普通输入框生成回答后改成 `Before用户新编辑After`，再点击替换，返回 `injection_target_changed`，新编辑不被覆盖、回答仍可复制。
4. 密码框选中合成内容后提问，原生不返回目标/选区/上下文，最终请求 selected_text 为空且 redacted=true。
5. 两个本机来源的网页（localhost 父页面、127.0.0.1 iframe）真实 AX 捕获两个来源地址。仅把父页面列入测试黑名单，iframe 的选中文字仍在请求前被正确移除；卡片无替换操作。

证据：`tmp/selection-actions/answer-ui-results.json`、`blocked-parent-results.json` 及本目录截图。首个测试捕获遇到 CUA 没有使测试进程真正前台，夹具按 PID 拒绝读取；重新明确聚焦后成功。只读框的 AX 选择辅助动作未形成实际选区，改用键盘选中并确认后继续；未将这些中间尝试记为通过。

人工复用：`npm run test:answer-card:ui`；网页父来源测试可在已构建夹具上添加 `--answers --web --blocked-parent`。仅访问本次合成测试页面及进程，不使用用户真实配置目录。

## 发布与边界

beta.13 的构建、严格 codesign、DMG 完整性/只读挂载、ASAR 与模型比对通过。安装包内含新增 command capture 导出。`release/testing/0.2.0-beta.13/` 提供安装包、复测清单、说明、截图、manifest 与 SHA-256；没有覆盖 `/Applications` 或真实数据目录。

未验证所有浏览器、PDF 阅读器、办公软件、终端及复杂编辑器的 AX 行为；选区不受支持时仍可能只能得到普通问题回答。只读选区保护不保证任意第三方应用提供的 AX 内容本身可信，模型提示将 selected_text 视为数据而非指令。

真人语音与回答质量、准确率/延迟分布、物理快捷键、多屏/睡眠实机、跨应用纠词跟踪、生产 HTTPS/邮件、整体云端清理和旧孤立音频、正式签名/公证/更新、多设备及其他平台继续未完成。整体替代目标保持进行中。
