# 云端按条删除与增量同步修复

版本：0.2.0-beta.8。日期：2026-10-08。

## 解决的问题

此前本机删除不传播到云端；另一个设备仍会看到旧记录。同步拉取还使用服务端最新时间作为起点，可能直接跳过本机未下载的记录。真正拉取新记录后，进一步发现 node:sqlite 的 BLOB 返回 Uint8Array，而服务端仅识别 Buffer，导致客户端落库报参数不足。

本批增加明确的删除范围、持久删除队列及服务端删除标记，修复本地游标、元数据序列化与账号归属。

## 当前行为

- 删除默认仍只影响本机。记录已关联当前服务器和账号时，可勾选“同时删除云端及其他同步设备上的这条记录”。本机保留期和清空本机历史不会自动升级成跨设备删除。
- 本机删除与云端删除任务在同一 SQLite 事务中保存。任务按 API 基地址、账号和记录 ID 隔离；退出、断网和重启不会丢失。删除队列只包含标识，不保留文字或音频。
- 同步开启后优先上传删除任务；每批最多 200 条，只确认服务端实际接受的 ID。网络失败最多自动尝试三次，耗尽后保留任务，可在“立即同步”中重试；设置页显示待云端确认的数量。
- 同步关闭时不发送删除。重新开启成功后恢复。切账号或切服务器不能替另一账号发送任务，迟到响应不能确认旧会话的任务。
- 服务端保存不含原文的永久删除标记，拒绝已删除 ID 的迟到上传；删除先于上传到达也有效。重复删除幂等，账号注销会级联清理这些标记。
- 拉取用本机持久游标，按服务器和账号隔离。记录与删除共用有序变更流，只有删除的页面也会推进游标；本机应用失败不推进。收到删除后取消相关任务并清除本机文字和所属录音，文件故障进入既有持久清理队列。
- 启动和每分钟同步拉取其他设备的变更；无登录或同步关闭时不传输历史。公网同步要求 HTTPS，本地回环开发地址允许 HTTP。同步模块在取令牌前拒绝不安全或无效地址；错误的旧地址不会阻止本地听写启动。
- 旧版未带账号的云端下载不会被自动认领并上传给新账号；只有经过当前已认证服务确认同一记录 ID 后，才接纳其更新或删除。

## 验证证据

- 完整 `npm run verify:all` 通过；新增真实服务进程、真实客户端 SyncEngine、两套设备目录和 SQLite 数据库联调，最终 14 组场景通过。215 条删除跨多批、多页检查无遗漏；含离线重启、账号隔离、上传迟到、删除先到、游标持久化、旧库迁移、账号注销等。
- 同步故障注入回归从 10 组扩为 18 组，新增部分确认、三次失败及重启后手动恢复、上传途中删除、迟到确认、旧服务不支持删除、应用失败不推进游标、公网 HTTP 与无效地址在读取令牌前被拒绝。
- 既有 11 组本机历史和真实文件清理场景继续通过；桌面接口新增当前账号/其他服务器/未登录的删除资格检查。
- 实际源码构建 Electron 界面通过隔离本地服务下载合成记录，显示删除范围复选框及说明。设置页对预置的合成待删除任务显示 1 条。修复确认按钮被挤窄的问题，并复核布局。此项没有通过 UI 确认删除；删除执行由上述真实客户端/服务端测试覆盖。
- 打包、严格递归签名、DMG 和包内 bundle 对照用于确认安装产物。最终结果与文件哈希见对应 release 目录中的 manifest。

## 部署与未完成范围

客户端要求服务端 `sync_status.history_deletion_version = 1`，并支持 `/transcription_history/delete` 和带 `deleted` 的增量拉取。本仓库服务端已实现；本次没有升级线上服务或配置其 HTTPS。旧服务未确认时任务保持待处理，不能宣称云端已删。

现有默认公网 HTTP 地址会被本批同步模块拒绝；需要部署更新后的服务并配置有效 HTTPS。此保护仅覆盖 SyncEngine，认证及其他网络客户端的统一 HTTPS 约束仍待收口，不能称为全应用网络安全验收完成。

两套临时设备目录模拟的是多设备同步链路，不能代替两台物理 Mac、真实网络长断连或生产服务验收。仍未完成旧孤立录音清理、云端整库清空/保留期的完整多设备语义、中文表达偏好、纠词学习、正式签名公证和真人跨应用测试。整体替代目标保持进行中。
