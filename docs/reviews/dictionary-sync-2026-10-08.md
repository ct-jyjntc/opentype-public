# 词典双向同步：实现契约

本批只读写源码，没有运行测试、类型检查、应用、服务端、迁移、构建或打包。beta.17 不包含此功能。

## 使用规则

词库同步默认关闭，与历史同步开关独立。登录只切换账号身份；首次开启前不会把本机词库复制或上传。开启时用户选择是否复制本机词库，开启后使用账号词库副本；已加入的账号可切回本机词库。关闭同步保留账号副本、未上传修改与当前词库选择；注销切回本机。所有网络请求检查原账号、完整服务地址、取消标记和开关，切服务地址先挂起旧请求。

复制本机词库只新增，保留账号词条原有释义。账号词库离线修改写入持久 outbox。词典界面、听写个性化、CSV 导入与备份均使用明确选中的词库。备份中不含账号身份、令牌和服务地址，恢复到账号词库时显示同步影响。

## 数据与网络

- 账号命名空间为完整规范化服务基址与用户 ID 的 SHA-256；本机词库固定为 `local`。
- 词条键为 NFC 规范化、去首尾空白、转小写后的词条 SHA-256。大小写变更仍是同一个词条；其他重命名是旧键删除、新键新增。
- SQLite 触发器将词条修改与 outbox 原子写入。应用远端页时临时抑制触发器，事务失败一起回滚。
- 服务端每个账号独立递增 revision，客户端以已知 baseRevision 提交。相同内容自动收敛，内容不同且版本变化产生冲突。
- 已接受操作保存 mutationId 与请求指纹，重发不再次写入。收据重放返回当前权威版本；没有更新本地操作时接收后续云端改动，有更新本地操作则重新基于已接受版本同步或显示冲突。
- 删除保留不含正文和释义的 tombstone；删除不存在的键也产生版本，避免较早创建迟到后复活。
- 客户端每批最多上传 200 条，先拉后推再拉，按服务端版本分页。与显示冲突的前 500 条上限无关；处理当前页后显示后续项。
- 接口为认证 POST `/user/dictionary/sync/status`、`/pull`、`/push`。旧词库 CRUD 和导入共享同一存储；旧表首次迁移后清除该账号旧行。账号外键删除级联清除词条、版本和收据。

## 并发与恢复

在请求期间继续编辑会产生新的 mutationId，旧请求完成不会抹掉后续修改。冲突选择同时核对云端 revision 与本地 mutationId；任一变化都要求重新查看。普通词条编辑/删除核对原词条内容，页面与备份预览绑定原词库 scope。

检测 `dictionary_cursor_ahead` 后暂停有效同步并显示恢复入口。用户明确确认后保留当前本机词条及所有待同步删除（包括超过冲突显示页的删除），清空旧 base/outbox 进度，基于版本 0 重建待同步项，再拉取全部当前服务端内容。云端缺词可能重新上传，存在不同内容/删除时要求选择。本机独立词库和其他账号不参与。

恢复入口只应在核对服务器恢复情况后使用；单靠整数游标只能发现服务器版本低于本机游标的回退，不能识别所有服务端备份替换情形。服务端持久 tombstone 和收据目前没有自动清理策略，避免使长期离线设备复活删除；大规模部署的留存、备份世代和压缩协议仍需单独设计。

词典同步服务需要随客户端部署，旧服务不会因新 UI 自动升级。实际两设备断网合并、迁移兼容和数据库性能未经本批运行验证。
