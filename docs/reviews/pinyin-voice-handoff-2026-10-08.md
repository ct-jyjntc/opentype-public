# 拼音组字与语音的交接

本批只修改源码与说明，未执行测试、类型检查、编译、界面验证、注册输入源或打包；beta.17 安装包不包含本批功能。没有修改真实用户配置或两款参考应用。

## 入口与顺序

普通听写、翻译、随便问，以及“粘贴上一条听写”和直接选区操作，共用组字交接。macOS 当前输入源是 OpenType 拼音时，先确认 IMK 已提交当前候选，再捕获语音使用的输入位置与上下文。右 Command、Fn 等仅产生修饰键事件的快捷键由桌面全局监听触发这条链路，不依赖 IMK 收到普通按键。

首页“试试听写”仅录音预览，不提交其他应用的组字，也不读取外部输入上下文。其他输入源沿用原有捕获路径；本协议不能控制 Chatterfly 或系统拼音的内部组字。

## 实现约定

1. `CaptureSession` 同步占用启动状态，通知 `preparing`，随后等待交接。麦克风和实时识别只在交接结束、会话仍有效时启动。识别 provider 在收到启动请求时固定。
2. 输入辅助库仅暂存原应用 PID、输入源、AX 输入框身份、选区范围与单调时钟截止时间，不读取组字正文。临时句柄不写入历史、网络或同步数据。
3. 桌面连接拼音组件独立目录中的 `voice.sock`。目录仅当前用户可读写，socket 权限为 `0600`；服务端核对对端 UID，用独立锁防止多实例抢占。消息只含动作、随机请求编号、PID、时间和结果状态。
4. `prepare` 绑定当时的原生控制器、客户端标识、组字修订、选区和标记范围。桌面再次核对原 AX 输入框与选区，才发送 `commit`。
5. 原生提交前重新核对会话、前台应用、输入源、用户交互修订与范围，并检查截止时间及连接是否已关闭。键盘输入、候选选择、鼠标点击或会话切换使旧请求失效。提交票据先作废，然后调用 IMK 提交；确认没有剩余 marked text 才发送 `committed`。
6. 桌面收到 ACK 后重新核对原输入框和输入源，再捕获已提交状态下的目标与上下文。选区文字和隐私过滤沿用原有链路。没有 ACK 或目标变化时，不自动开始录音或继续粘贴。

握手最多等待 1.5 秒。这是启动请求有效期，不是录音时长限制。socket 读取非阻塞，运行在原生主队列；等待期间不启动同步子进程，也不轮询睡眠阻塞 Electron 主线程。服务只保留少量连接，超时关闭；退出清理连接与 socket，进程意外退出后的旧 socket 由持锁的新实例清理。

## 取消与失败

- 等待期间松开长按快捷键、再次触发停止或按 Esc，会取消启动；不等待旧请求结束后再录音，也不发送未开启录音的尾包请求。
- 旧请求完成不能清空或启动新会话。目标句柄、socket 和计时器在成功、失败及取消路径均收尾。
- 新录音、关闭选区卡片、休眠/锁屏和退出取消在途选区捕获；粘贴请求延续原有独立取消机制。更新安装和同步调度将选区准备视为忙碌状态。
- 超时、组件缺失/旧版本不支持、组字未清空和目标变化分别显示说明。失败不尝试按回车、剪贴板粘贴或再次提交作为隐式补救。
- 取消与原生 `insertText` 已开始执行可能同时发生。已提交的拼音属于原来的用户输入，不回删、不重放；取消保证不继续开始语音或交付语音结果，不能撤回已经完成的拼音提交。

状态接线包括共享 `VoiceState`、快捷键状态协调、浮窗和首页试听按钮。原生新接口需与桌面代码一起重新构建；本批没有生成可安装组件。未确认第三方应用的 IMK/AX 一致性、输入源激活时序或握手实际耗时，不能据源码写入宣称运行效果已经验证。

## Windows 对应实现（2026-10-09）

Windows 已接入相同的桌面准备/取消入口，使用 TSF 原线程消息窗口和固定大小的 prepare/commit 消息。原生工作线程等待响应，UIA 核对原进程、输入框和选区；私有取消事件防止超时请求随后写入。确认 TSF 提交后才捕获语音目标，支持 x64 桌面向 x86 输入组件交接。Windows 不复用 macOS 的 Unix socket 路径。详见 [Windows 拼音实现](windows-pinyin-2026-10-09.md)。这一补充同样没有运行、注册或打包。
