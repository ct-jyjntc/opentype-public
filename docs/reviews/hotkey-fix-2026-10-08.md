# 快捷键失效排查与修复

## 安装版的证据

- 排查对象：`/Applications/OpenType.app`，包内版本 `0.2.0-beta.2`，运行进程 PID 3951。
- 实际配置的听写快捷键为 `RightCommand`，提问为 `Fn+Space`，翻译为 `Fn+LeftShift`。
- 通过只读 `CGGetEventTapList` 检查，安装版两条 tap 均为 disabled，event mask 为 4096（仅 flagsChanged），没有可用的完整键盘监听。
- 系统设置的“输入监控”列表为空；辅助功能已有授权。旧版只检查辅助功能，没有单独检查监听权限或向用户展示真实 tap 状态。辅助功能授权不能代替对监听状态的检测。
- 无法从旧版保留下来的信息确定第一次禁用的精确时刻，因此不把“回调超时”或“睡眠”断言为此次唯一触发因素。

## 确认的代码缺陷与改动

1. 旧 watchdog 调用 `stopKeyboardMonitor()`，同时清掉 `gCallback` 并停掉自己的定时器，然后只重新安装 tap。这会留下一个没有回调、也没有后续恢复能力的监听。修复为独立销毁 tap、保留回调与恢复定时器，正确移除并 invalidate 旧 Mach port。
2. 旧 tap 内同步执行前台上下文读取、配置写入、IPC 和录音启动，可能耗尽系统回调时限。现在原生回调只解码事件，在 `setImmediate` 中执行业务逻辑。停用后会丢弃旧队列事件。
3. Koffi 回调每次启动注册但从不注销，存在 8192 个槽位耗尽风险。现在启动幂等，停止后注销，并对权限未就绪保留可重试注册。
4. 检查 `CGPreflightListenEventAccess`，暴露 inputMonitoring、active、callbackRegistered 和不含按键内容的计数。设置页显示真实状态、权限入口和“重新连接”；失败启动自动打开主窗口，避免后台静默失效。
5. 右 Command 等物理单修饰键可保存并保留左右区分；单修饰键在松开时触发，Cmd+C 等常用组合不会意外开启听写。补齐 Control/Command 名称和数字键码，Fn+Shift 不依赖两个修饰键的按下顺序，按住说话释放任一所需修饰键即可结束。

## 验证

- `npm run verify:all`：退出码 0，类型检查、核心、IPC、录音、桌面服务、原生冒烟、网关、本地隔离集成及服务端测试通过。
- `npm run test:keyboard:host`：通过。使用真正的 Swift 库与 Koffi 桥接，测试原生事件数据至 start/stop、回调异步退出、数字与修饰键解码、停止后丢弃队列；连续禁用真实 CGEventTap 两次，均由定时器恢复且保留回调；8300 次启动/停止无回调槽耗尽。
- `test:core`：43 项通过，含右 Command 左右区分、Cmd+C 不误触、Fn+Shift 两种顺序、修饰键释放停止。
- Electron 源码界面：隔离资料目录保存 RightCommand 成功，重载后显示监听已就绪。
- 原生回归测试通过编译开关提供进程内故障注入，不向系统投递键盘输入，测试导出不进入安装包。

## 尚需真人验收

UI 自动化的 F8 被直接发往测试窗口，检查该进程的系统 tap 未观察到这次输入，无法据此验证物理全局按键。没有将首页按钮录音或进程内事件测试当作真人快捷键成功。

安装版仍需按随包清单检查系统授权，并实按 RightCommand/Fn，验证跨应用开始、停止、取消以及睡眠恢复。此次代码与自动化验证通过，不代表 TypeLess 全部替代目标完成。
