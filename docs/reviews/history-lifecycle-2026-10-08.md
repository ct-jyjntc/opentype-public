# 本机历史与录音生命周期修复

版本：0.2.0-beta.6。日期：2026-10-08。

## 问题与结果

此前手动删除、清空或到期清理只删除 SQLite 的历史行，本机录音可能遗留。识别重试和云端旧记录可能再次写回已删除的 ID。删除与文件写入同时发生时，仅先删文件也可能产生新的遗留文件。

现在，数据库事务先保存只包含 ID、删除时间与清理状态的删除标记，再删除历史内容。文件清理只访问应用音频目录下该 ID 对应的 WAV/Ogg/WebM，不采用历史行中可能来自同步的文件路径。清理等待该 ID 的写入结束；后续写入、重试和同步旧记录不能复活这个 ID。删除还会取消对应的录音与识别请求，包括使用不同 abort ID 的旧前端请求。

不能清理的文件保留待办，手动操作给出明确提示，启动后及每六小时重试；缩短本机保留期立即清理。更改保留期后，即使文件暂时清理失败，保存的设置也会正确显示。其他文件和符号链接指向的目标不作为删除对象。

## 明确的剩余边界

- 删除标记只在本机生效，尚未实现按条删除的云端队列和跨设备传播。云端旧副本被拉取时不会恢复到本机，但并不意味着云端副本已删除；界面已说明这一点。
- 对升级前已失去数据库归属的旧录音，本批没有盲目扫描删除；需要单独设计可审查的存储清理。
- 不承诺安全擦除 SSD、系统备份或导出的音频副本。
- 本批没有重新测量真人语音准确率或跨应用插入延迟，未完成整体替代目标。
