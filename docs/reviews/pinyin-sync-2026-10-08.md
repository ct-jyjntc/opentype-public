# 拼音短语同步与原生重载

本批只完成源码与接口资料核对。没有执行测试、类型检查、编译、服务启动、数据库迁移、系统输入法注册或打包；现有 beta.17 包不包含本批代码。

## 用户可见行为

- 设置 → 拼音输入 → 自定义拼音短语有独立同步面板。此开关默认关闭，不依赖历史同步或语音词典同步；登录不会自动上传本机词库。
- 首次启用时用户选择是否复制本机短语；不选择则仅使用账号词库及其本机副本。开启后使用账号词库，也可切回始终不上传的本机词库。
- 本机副本可离线修改，新增、改权重、改拼音/文本和删除进入持久队列。关闭同步保留当前副本和未上传操作；注销切回本机词库。
- 同步只包含明确创建或导入的文本、拼音、权重及删除状态。原生选词学习、候选记录、输入内容、语音历史和账号凭据均不在短语载荷中。
- 相同词条和拼音定义同一个短语；同词不同拼音可分别保存。权重冲突和编辑/删除冲突要求选择一方。确认同时绑定本地修改 ID 和远端版本，拒绝过期弹窗。
- 编辑及文件导入绑定原词库和原数据版本；切换账号/词库会关闭原编辑入口。后台同步修改后，尚未保存的编辑不能直接覆盖新数据。

## 持久化与迁移

桌面 SQLite 的 `pinyin_preferences`、`pinyin_words`、`pinyin_accounts`、`pinyin_base` 和 `pinyin_outbox` 为权威数据。偏好和词条修改在同一事务中提交；词条修改与待同步操作也一起提交。账号范围以完整服务基址、用户 ID 的 SHA-256 隔离，独立于语音词典范围。

旧 `settings.json` 首次读取后迁移到数据库。之后该文件只作为原生输入法的当前词库副本，采用原子替换写入 `version:2`、不透明词库范围、拼音偏好和当前词条，不携带凭据。数据库与文件不能组成同一个事务，因此写文件失败时保留数据库结果，显示原生词库未更新并定期重试。

如果数据库被清除、只剩一个账号范围的原生副本，迁移会把短语恢复到原来的不透明账号范围，不转成另一账号或本机词库，也不会仅因登录就上传。需要进入对应账号并明确开启同步后再比对。

原生单个词库最多加载 50,000 条自定义短语。多设备合并超过此数时，全部记录仍在数据库，可导出、删除或整理；原生暂不加载该词库的自定义短语并显示提示，不保留先前账号词库作为替代，也不静默截取一部分。已有超额词库允许继续减少条目，不能继续新增。

## 服务端协议

认证 POST：

- `/user/pinyin/sync/status` 返回协议版本、账号词库世代 `epoch` 和递增 `revision`。
- `/user/pinyin/sync/pull` 携带 epoch 和游标，最多返回 200 项及下一页状态。
- `/user/pinyin/sync/push` 携带 epoch 和最多 200 个操作；每个操作包含短语键、操作 ID、已知版本和期望内容。

短语键为规范化文本与拼音的 JSON 数组的 SHA-256。服务端比较已知版本，内容一致自动收敛，不一致产生冲突。成功操作记录持久幂等收据；重复请求不重复增加版本。删除只保留键和删除状态，不在 tombstone 中保留短语正文。账号删除级联清理这套表。

世代变更或游标回退要求用户确认重新对齐：保留所有当前短语和待同步删除，清空旧同步基线，重新读取服务端并显示差异。所有 pull/push 请求和响应绑定同一 epoch；每个网络等待后再次核对账号、完整服务地址、开关、取消与会话代数。切换服务先挂起旧请求，不向新地址发送旧账号凭据。

重建同一世代的旧服务器备份，若其版本号仍不低于客户端游标，仍不能仅靠整数版本识别全部回退情况。该限制与备份世代的管理有关，未在本批宣称全面解决。

## 原生输入法衔接

原生组件监视配置目录的原子替换，合并短时间内的多次更新。已开始的组字会话保留原词库，结束或取消后释放；全部旧会话退出后才在后台准备新词库。重建期间显示状态，准备失败保留数据库及设置，可重试。准备时又发生变更会继续采用最新版本，不把旧的完成回调当作最新词库。

个人选词学习按本机/账号词库范围使用不同 Rime user_dict；只改变词库文件名，学习内容不经同步接口上传。保留旧本机 `pinyin_simp.userdb`，账号学习使用不透明名称。清除学习确认保存原词库身份，准备中或身份改变时拒绝清除。

核对了 Rime 1.13.1 的公开 `UserDictionaryComponent::Create` 实现，其读取 `translator/user_dict` 和 `enable_user_dict`，支持这两个配置入口；此源码依据不等于已运行验证选词或同步效果。
