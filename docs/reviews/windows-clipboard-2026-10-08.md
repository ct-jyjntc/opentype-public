# Windows 剪贴板独立恢复：源码批次

本批只写入源码、构建定义和文档，没有编译、运行测试、类型检查、GUI 验收或打包。实际用户配置与已交付的 beta.17 安装包未改动。

## 新的交付链路

1. 原生输入桥先核对原窗口、具体输入框、内容、选区与修饰键。
2. `ClipboardGuard.exe` 在独立进程中通过 OLE 完整取得可回放的剪贴板格式，保存原内容的内存副本，回复准备就绪；这一阶段不发布听写文字。
3. 父进程重新核对输入目标，再发出发布请求。子进程预先复制全部要发布的句柄，在 `OpenClipboard` 锁内检查最初序列号、清空并设置 Unicode 文本与可选 CF_HTML。
4. 父进程收到已发布序列号，再次核对目标、剪贴板和按键，发送一次 Ctrl+V，并通知子进程等待目标消费。原输入验证链路不变，不因超时或结果不确定重复粘贴。
5. 子进程收到已发送通知后等待约 1.2 秒恢复。显式取消、应用退出或父进程异常退出会提前请求恢复；丢失发送通知时也有超时恢复。

## 恢复所有权

- 原内容由独立进程持有，恢复不依赖 Electron 的定时器。父进程通过仅含 SYNCHRONIZE 权限的进程句柄被观察，进程退出不会被 PID 复用误认成仍然运行。
- 恢复前先复制好要交还给系统的句柄，再取得剪贴板锁。在同一把锁内检查序列号和原生窗口所有者，条件不符时放弃恢复，不覆盖用户之后复制的新内容。
- 如果剪贴板暂被占用或内存分配暂时失败，子进程保留原副本并继续重试。系统设置格式时部分失败也保留副本，按实际最新序列号继续恢复。
- 同一用户、同一 Windows 会话内使用互斥锁，避免多个 OpenType 配置同时保存和覆盖剪贴板。新输入先请求前一次恢复，前一次未释放时回到手动复制。
- 快照取得阶段卡住且尚未授权发布时，可以结束子进程；一旦发出发布请求，父进程只请求恢复，不强制结束持有原副本的进程。

## 格式、数据和边界

- 保留可复制的 HGLOBAL、位图、传统图元文件和增强图元文件。发布前校验格式、媒介类型、单一内容表示与唯一格式编号。
- IStream/IStorage、调色板、需要专用所有者生命周期的格式、多索引虚拟文件或不完整快照不进入自动发布。任何格式无法完整复制时保留原剪贴板，听写文字可手动复制。
- 归档最多 128 个可回放格式，总容量限 256 MiB；图片和图元文件也计入容量。该上限是剪贴板快照保护，不是录音时长上限。
- 请求使用有界的匿名共享内存与显式继承句柄，载荷上限 16 MiB；命令行只传句柄数字，不传文字或路径。内存对象及互斥锁按当前用户和 SYSTEM 配置 ACL。
- 应用不把剪贴板快照写入用户配置、日志或恢复文件。此设计覆盖主应用异常退出；整机断电、同时终止父子进程、子进程自身崩溃不具有磁盘恢复能力。
- 系统或剪贴板管理器改变序列号时会保守放弃恢复，不根据“看起来一样”的文本猜测所有权。第三方 OLE 提供者可能阻塞，仍需后续实机验证兼容性和耗时。
- 目标焦点核对、剪贴板核对和 Windows 输入消息队列不能组成跨进程原子事务，极短的并发操作窗口仍由既有结果核对与“不确定、不重发”策略处理。没有据源码宣称任意编辑器可靠率或零延迟。

## 文件与构建接入

- `native/windows/ClipboardGuard.cpp`：独立备份、发布、恢复进程。
- `native/windows/ClipboardData.h`：OLE 格式物化、媒介副本和容量计算。
- `native/windows/ClipboardLease.{h,cpp}`：父进程生命周期、明确句柄继承与等待。
- `native/windows/ClipboardProtocol.h`：共享握手和有界请求契约。
- `native/windows/Input.cpp`：准备、发布前后核对、发送通知与退出恢复。
- CMake 与 Windows NSIS 资源定义加入 `ClipboardGuard.exe`。未生成二进制或安装包。
