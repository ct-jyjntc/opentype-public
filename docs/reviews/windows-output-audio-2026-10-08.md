# Windows 外放控制与恢复：源码批次

本批只修改源码和构建定义，没有运行编译、类型检查、测试、GUI 验收或打包。没有改动实际用户配置；beta.17 DMG 不包含这些新增能力，也没有生成 Windows 安装包。

## 操作范围

- 复用录音偏好：保持原音量、降到原音量的 20%、静音。默认不修改音量，偏好从下一次录音开始生效。
- `OutputAudio.exe` 通过 Windows Core Audio 访问系统默认播放设备和默认通信设备，按 endpoint ID 去重，仅操作 render endpoint。应用手动指定到其他设备的声音不在控制范围内。
- 录音开始时启动独立子进程；停止收音、取消、休眠及退出沿用现有录音生命周期关闭 stdin。即使 Electron 崩溃，子进程也能通过管道断开尝试恢复。输入管道采用可中断轮询，避免取消与阻塞读取的竞态。
- 默认设备变化时，先尝试恢复旧设备，再控制新设备。静音优先控制静音属性，降低音量控制 master scalar。已静音或零音量的设备本次不接管。

## 所有权与持久恢复

- 修改前写入恢复记录，记录原值、拟应用值与状态，之后才调用系统接口。成功应用后重新读取设备实际值，处理设备音量量化。
- 卷回调带本进程事件标识，外部更改受控属性后放弃该设备，之后不反复接管。恢复前再次比较当前值，只尝试恢复仍匹配本应用写入值的属性；用户调整后即使又调回，也会通过运行期间的回调记录放弃所有权。
- 记录固定为 `%APPDATA%\dev.opentype.output\lease.bin`，不同 OpenType 配置共用。CLI 仅接受 `duck`、`mute`、`recover`，不允许传入任意恢复文件。
- 使用当前用户及 SYSTEM 的文件 ACL、所有者检查、拒绝最终路径的重解析点、有界读取、CRC32 和完整结构校验。原子替换前刷新磁盘。记录损坏或不可写时停止新的音量接管，并保留恢复记录供后续处理。
- 同一用户、同一 Windows 会话内通过命名互斥锁串行运行。这里不承诺远程会话之间共享音频设备的行为。
- 断开的设备保留记录，运行期间定期重试，下次应用启动继续恢复。恢复失败与记录清理失败会显示在设置页，不能把退出或删除失败显示成恢复成功。
- Windows Core Audio 没有原子比较并交换音量接口；比较、写入与外部修改之间仍存在系统级竞态窗口。离线期间的用户修改只能按当前值判断，不能靠持久记录重建完整操作历史。

## 桌面接入

- `src/main/services/output-audio.ts` 按平台选择原生执行文件和参数，串行处理录音切换与恢复，恢复队列只保留一个任务，避免后台间隔累积。
- 正常释放先关闭 stdin，保留恢复时间；只有超时才尝试结束异常子进程。退出应用时不立即调用 Windows 的强制终止接口，未恢复记录继续留存。
- 子进程报告仅接受既定状态码；失败、设备暂不可用、用户改音量、恢复待续及互斥占用分别展示。旧录音的提示不能写进新录音胶囊。
- 设置页显示当前状态和手动“重试恢复音量”；胶囊收起后仍可查看。正在录音时禁用手动恢复，后台恢复不会开启录音或更改用户偏好。IPC 只允许主窗口的主 frame 调用。
- macOS 沿用已有独立进程，补入共享状态界面和已静音设备的启动确认，避免界面长期停留在“正在调整”。
- CMake 和 Windows NSIS 资源定义包含 `OutputAudio.exe`，本批没有运行这些构建步骤。

主要文件：`native/windows/OutputAudio.cpp`、`native/windows/PrivateStorage.h`、`src/main/services/output-audio.ts`、`src/shared/output-audio.ts`、`src/main/index.ts`、`src/preload/desktop.ts`、`src/renderer/pages/settings.tsx`。
